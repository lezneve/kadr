# kadr / що перевірено і що ні

стан на 2026-11-11, release candidate 0.1.0-rc.1. машина та умови — measurements.md.

**про права.** на тестовій машині вимкнено uac (`EnableLUA = 0`), тому кожен процес облікового запису, навіть explorer, має повний токен адміністратора. «звичайний користувач» перевірено так: тести створюють токен, який uac видав би звичайному сеансу (`LUA_TOKEN`, група administrators вимкнена, рівень цілісності medium), і запускають kadr з ним (`tests/common.ps1`, `Start-Kadr -Unelevated`). решта тестів іде з тими ж правами, що й explorer на цій машині. деталі — docs/incidents.md.

## як перевіряли

жоден автоматичний тест не емулює клавіатуру чи мишу. kadr керується повідомленнями у його власні вікна (`WM_HOTKEY`, `WM_TRAY`, повідомлення миші в overlay, клавіші в меню трею й у вікно налаштувань) — це ті самі гілки коду, крім доставки натискання системою.

## перевірено

| сценарій | як | результат |
|---|---|---|
| kadr не вимагає прав адміністратора | session: старт зі стандартним токеном | працює, `elevated=False integrity=0x2000` |

| copy+save | session | файл і буфер одночасно |
| трей: ліва кнопка, меню, «capture region» і «quit» з клавіатури | session | ✔ |

## не перевірено

позначено як невідоме, а не як працююче.

**обладнання — не перевірено:**
- **кілька моніторів**, від'ємні координати, монітор ліворуч чи вгорі від основного;
- **різний масштаб dpi на різних моніторах**: overlay через монітори з різним dpi (рамка, мітки й підпис беруть dpi монітора під кутом виділення), вікно налаштувань при перетягуванні між моніторами (`WM_DPICHANGED`);
- **hdr-дисплей** (`BitBlt` на hdr, за звітами, дає неправильні кольори);
- 4k і кілька 4k: пікова пам'ять, час появи overlay, вартість перемальовування великих виділень;
- windows 10.

**з реальним вводом** (`tests/input.ps1` або чеклист нижче):
- справжнє перетягування мишею, вигляд overlay під час руху, курсор-хрестик, підказка, підпис, **мітки обрізу на виділенні** (я не дивився знімків overlay: вони містять екран користувача);
- `ctrl+shift+printscreen` реально доходить;
- overlay отримує фокус клавіатури, esc працює без кліку;
- запис гарячої клавіші реальними клавішами, особливо `printscreen` (приходить тільки як key-up) і комбінації з `win` (windows може відкрити меню «пуск»);
- вікно налаштувань отримує фокус при відкритті з трею;
- вибір папки через системний діалог;
- перемикач «start with windows» (пише в `HKCU\...\Run`; автоматично не перевіряли, щоб не чіпати реальний автозапуск);
- іконка трею при зміні теми, після перезапуску explorer.

**обмеження, відомі з коду:**
- стандартне меню трею win32 у темній темі windows лишається світлим: документованого api для темних win32-меню немає;
- контекстне меню поля «file name» теж світле з тієї ж причини.

## перед релізом обов'язково (рішення команди)

0. docs/manual-checklist.md — короткий список для ручного проходження.
1. `tests/input.ps1` — запускає людина, без прав адміністратора.
2. docs/overlay-check.md — ручна перевірка overlay на сітці `tests/calibration.ps1`.
3. чеклист нижче.

мультимонітор, різний dpi на моніторах і hdr, поки не перевірені на реальному обладнанні, лишаються в обмеженнях релізу (README).

## чеклист для живої перевірки

1. `cargo build --release`, запустити `target\release\kadr.exe --trace` з термінала.
2. `printscreen` (клавіша області) → overlay; перетягнути → вставити в paint, розмір збігається з підписом; мітки обрізу в кутах виділення.
3. `printscreen` → esc; → права кнопка; → клік без руху, потім перетягування.
4. `alt+printscreen` над вікном і над робочим столом (має зняти монітор). `ctrl+shift+printscreen`.
5. трей: ліва кнопка, права кнопка й кожен пункт; enter на іконці (win+b, стрілки).
6. settings: tab по рядках (мітки обрізу йдуть за фокусом); клік по «capture region», натиснути нову комбінацію → вона працює, стара ні; esc під час запису; backspace вимикає клавішу; зайнята комбінація (win+shift+s) → червоне повідомлення.
7. settings: «send to», папка через діалог, ім'я файла з недопустимим символом (`:`) → червоне повідомлення, нічого не збережено; «start with windows» → з'являється й зникає `kadr` у `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
8. перемкнути тему windows — вікно й іконка міняються.
9. на машині з двома моніторами: область через обидва; другий ліворуч від основного; різний масштаб.
