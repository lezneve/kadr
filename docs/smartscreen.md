# kadr / smartscreen та інші попередження windows для непідписаного exe

стан: `kadr.exe` і `kadr-0.1.0-rc.1-setup.exe` **не підписані** (немає сертифіката підпису коду). це не помилка програми, але користувачі побачать попередження. нижче — чого чекати і що можна зробити. ці попередження на тестовій машині **не відтворювались** (файл, зібраний локально, не має позначки «завантажено з інтернету»), тож опис спирається на документовану поведінку windows, а не на власні знімки.

## що побачить користувач

**1. smartscreen («windows захистив ваш пк»).** з'являється, коли користувач запускає файл, завантажений браузером (файл має позначку mark-of-the-web, потік `Zone.Identifier`), а в microsoft немає «репутації» цього файла чи його видавця.
- текст: «windows захистив ваш пк … невідомий видавець».
- кнопка «запустити все одно» прихована за посиланням «докладніше».
- для непідписаного файла репутація прив'язана до **конкретного файла (хешу)**: кожна нова версія kadr починає з нуля.
- для підписаного — до **сертифіката**: репутація переходить на наступні версії.

**2. zip-архів.** якщо розпакувати завантажений zip провідником, позначка «з інтернету» переходить на `kadr.exe`, тож попередження буде й для портативної версії.

**3. smart app control** (windows 11, нові інсталяції 22h2+). у режимі «увімкнено» блокує непідписані застосунки без репутації **без кнопки «запустити все одно»**. на тестовій машині вимкнено (`VerifiedAndReputablePolicyState = 0`), тож не перевірено. користувачу з увімкненим smart app control непідписаний kadr запустити не вдасться — тільки вимкнувши smart app control (і ввімкнути його знову потім неможливо без перевстановлення windows), чого не варто радити.

**4. антивірус.** kadr копіює себе (інсталятор у `%LOCALAPPDATA%\Programs\kadr`, деінсталятор — у `%TEMP%`) і запускає копію. це звичайна поведінка інсталяторів, але евристики антивірусів інколи реагують на непідписані файли з такою поведінкою. microsoft defender за всі прогони тестів на цій машині не спрацював ні разу; інші антивіруси не перевірялись.

**5. uac.** не з'являється: маніфест оголошує `asInvoker`, інсталяція — для поточного користувача, права адміністратора не потрібні. маніфест також вимикає евристику windows «installer detection», яка інакше могла б просити права для файла з «setup» у назві.

## що можна зробити

від найдієвішого:

1. **підписати код.** варіанти:
   - **azure trusted signing** (сервіс microsoft) — зазвичай найдешевший шлях; доступність для фізичних осіб і країн обмежена, перевірити умови;
   - **ov-сертифікат** від центру сертифікації (на компанію або фізичну особу, з перевіркою особи);
   - ev-сертифікат раніше давав репутацію одразу, але microsoft цю перевагу прибрала: тепер репутація набирається й для ev; ціна вища, переваги для smartscreen немає.
   підписувати треба той самий `kadr.exe` (інсталятор — його копія, підпис зберігається). підпис і мітку часу робить `signtool` з windows sdk на етапі збирання; у `tools/release.ps1` це один крок після `cargo build`.
2. **подати файл на аналіз microsoft** (microsoft security intelligence, «submit a file» як розробник програми) — для хибних спрацювань defender і щоб пришвидшити репутацію.
3. **публікувати sha-256** поруч із файлами (`tools/release.ps1` уже створює `.sha256`) і писати в описі релізу, як перевірити: `Get-FileHash kadr-0.1.0-rc.1-setup.exe`.
4. **чесно попередити в описі релізу**, що файл не підписаний і windows може показати smartscreen; пояснити «докладніше → запустити все одно» і що робити зі smart app control (див. вище).
5. **не перевипускати файли без потреби**: для непідписаного exe кожна збірка скидає репутацію.

## рекомендація для першого публічного релізу

- мінімум без витрат: пункти 3–5 (sha-256, попередження в описі, стабільний файл).
- до стабільного 1.0: підпис коду (пункт 1), бо інакше кожне оновлення знову показує smartscreen, а користувачі зі smart app control не зможуть запустити kadr взагалі.
- рішення щодо сертифіката — за командою: це витрати й перевірка особи/компанії, не технічне питання.
