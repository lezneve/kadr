# kadr 0.1.0-rc.1 / готовність до першого публічного релізу

стан на 2026-11-11. статус лишається **release candidate**: стабільним не позначено, нічого не опубліковано.

## передрелізний аудит

| вимога | результат | як перевірено |
|---|---|---|
| інсталятор не видаляє налаштування без окремого підтвердження | **виправлено.** раніше видалення одним питанням прибирало й налаштування. тепер — окреме питання, за замовчуванням «ні». установка й оновлення налаштувань не чіпають взагалі | `tests/install.ps1`: «ні» → `settings.ini` незмінний; «так» → прибрано |
| повторне встановлення оновлює без втрати налаштувань | ✔ `settings.ini` незмінний байт у байт; новий kadr працює з тими самими клавішами | install.ps1, обидві теми |
| перейменування exe не вмикає інсталятор випадково | **виправлено.** раніше будь-яке ім'я з «setup» вмикало інсталятор. тепер тільки `kadr-setup` / `kadr-<версія>-setup`, з « (n)» від браузера | unit-тест (6 імен «так», 11 «ні»); install.ps1: `kadr-portable`, `kadr-setup-old`, `setup`, `kadr (setup)` → звичайний kadr; `…-setup (1)` → інсталятор |
| закриття всіх процесів при оновленні й видаленні | ✔ kadr і його процес налаштувань закриваються; нових залишків немає. **виправлено дорогою:** (1) інсталятор чекав завершення старого kadr, не обробляючи повідомлень — тепер обробляє; (2) заміна exe одразу після виходу старого kadr могла впертися в тимчасове блокування файла — тепер повторює до 5 с; (3) прибирання папки програми прихованим `cmd` не працювало зі стандартним токеном — замінено копією деінсталятора в `%TEMP%`, з повторами | install.ps1 |
| поведінка з увімкненим uac | ✔ з токеном, який uac видає звичайному сеансу: інсталятор без підвищення прав, установка, запуск kadr стандартним користувачем, видалення. маніфест `asInvoker` вимикає «installer detection» для назви з «setup». **не перевірено**: машина з реально увімкненим uac (на тестовій uac вимкнено, а вмикати його — зміна системи з перезавантаженням); запуск інсталятора «від імені адміністратора» при увімкненому uac (тоді kadr стартує через explorer, щоб не успадкувати права адміністратора) | install.ps1, розділ 5; перевірка маніфесту в exe |
| smartscreen для непідписаного exe | описано: docs/smartscreen.md | документація windows; на машині не відтворювалось |

**ще одна знахідка аудиту:** відкриття вікна налаштувань переписувало `settings.ini` (поле імені файла повідомляло про «зміну» при створенні), тобто ручні коментарі у файлі зникали. виправлено: збереження тільки коли значення справді змінилось.

## залишкові ризики

**критичних не знайдено.** решта, від важливішого:

| ризик | вплив | що з ним робити |
|---|---|---|
| exe не підписаний | smartscreen при першому запуску; smart app control (якщо ввімкнено) блокує kadr повністю | docs/smartscreen.md; підпис коду до 1.0 — рішення команди |
| ручні тести вводу ще не пройдені | доставка реальних клавіш, фокус overlay, запис комбінацій справжніми клавішами не підтверджені на фінальній збірці | manual-checklist |
| кілька моніторів, різний dpi, hdr, 4k | геометрія, масштаб і кольори не перевірені на реальному обладнанні | лишаються в обмеженнях README; overlay-check розділ «кілька моніторів» |
| windows 10 | не перевірено зовсім; шрифти мають запасні варіанти | обмеження README |
| увімкнений uac на реальній машині | перевірено лише еквівалентним токеном | ручна перевірка на машині з uac |
| антивіруси, крім defender | самокопіювання інсталятора/деінсталятора може дати хибне спрацювання | при скаргах — подати файл виробнику; підпис коду зменшує ризик |
| тимчасова копія деінсталятора лишається в `%TEMP%` | ~0.4 мб до очищення temp windows | задокументовано; так роблять поширені деінсталятори |
| меню трею й контекстне меню поля світлі в темній темі | косметика | лише недокументовані api; лишаємо обмеженням |
| з вимкненим uac і зниженими правами kadr не додає іконку трею | лише на машинах з uac вимкненим і штучно зниженими правами | kadr повідомляє про це прямо |

## рекомендація

якщо ручні перевірки (manual-checklist, overlay-check) пройдуть без підтверджених проблем, kadr 0.1.0 можна публікувати як перший публічний реліз lezneve/kadr з такими умовами:
- позначити його 0.1.0 (не 1.0) і чесно перелічити обмеження з README;
- опублікувати sha-256 і попередження про smartscreen;
- підпис коду — окреме рішення до 1.0.
